# Floating Islands

Small black islands that float over every app, Space and full-screen window on the display with the pointer. Heimdall uses them during conversations through the `islands` CLI, which writes the files the app watches. This is a prototype; it goes into Heimdall later.

## Run

```
scripts/build.sh                                  # build/FloatingIslands.app + build/bin/islands
build/FloatingIslands.app/Contents/MacOS/FloatingIslands [--max-hours N]   # quits itself after N h (default 24; 0 = no limit, Heimdall supervises it)
build/FloatingIslands.app/Contents/MacOS/FloatingIslands --parent-pid PID     # quits when that process exits (Heimdall passes its own pid)
demo/shadow_demo.py [--speed 1] [--hold 6]        # simulated shadow, about 27 s; starts the app if needed
demo/showcase.py                                  # the showcase: sample data; up 30 min, then clears itself
build/bin/islands clear && build/bin/islands quit # clear it sooner
```

Beta: the Floating Islands helper has had little live use outside the maintainer's Mac; expect rough edges.

Two builds of the same app: this Swift package, and `crates/islands` in Rust (objc2 + AppKit + Core Animation; binaries `FloatingIslands` and `islands`, the same flags, file protocol, look and motion). `scripts/bundle_islands.sh` puts the Rust build into Heimdall (`ISLANDS_HELPER=swift` bundles this one instead, the rollback). The Swift rollback predates Goals (31 Oct): it still draws To do, moves due Scheduled items into it and lets `put`/`rm` touch plan lists, so it must not be bundled with a Heimdall that writes Goals. Rust: `nice -n 19 cargo build --release -p islands -j 2`, then `target/release/FloatingIslands` and `target/release/islands`; every lab flag below works on both (`lab/rust_port_real.sh`, `lab/perf.sh` and `lab/tools/compare_shots.py` compare them; numbers in `lab/rust-port-measurements.md`).

The app is an agent app (no Dock icon or menu bar) and runs only while launched; nothing is installed. `islands quit` quits it. The demo and every lab script clear all islands and quit the app on exit, including on Ctrl-C or kill. `FLOATING_ISLANDS_DIR` moves the data folder; lab runs use `lab/data/<name>`.

## Files

Data folder: `~/Library/Application Support/FloatingIslands/`
- `islands/<id>.json`: one island. Create, rewrite or delete it and the island appears, changes or leaves at once (one kqueue watch, no polling). Write with a temp file plus rename (the CLI does).
- `visibility.json` (written by Heimdall's ⌃⌘, and Show Islands, or `islands hide-all` / `show-all`): `{"hidden": true}` takes every island's window off screen at once; missing or false shows them. No island file or state changes: shown again, every island is back where it was, open or closed. While hidden, an open viewer is not closed by clicks elsewhere. While hidden, an island with news comes back alone for a moment (`model/flash.rs`): it arrives, turns done, failed or waiting, gets a question or a new waiting item, or a viewer or note shows new content (stage and progress updates do not count). It fades in at its place (0.3 s) with one soft pulse in the news's colour, stays 4 s after its latest news, and fades out (0.6 s). The pointer over it, opening it, or a question or bell not yet seen holds it; released, it lingers 1.5 s. Islands up on their timers leave together; more news extends them and pulses at most every 1.5 s. One one-shot timer, nothing at rest. Rust build only (the Swift rollback ignores it).
- `streams.json` (written by Heimdall's Show Islands on Streams): `{"shown": true}` puts every island window in screen shares, streams and screenshots; missing or false keeps them all out (unshared), the default. Watched: a change applies at once. A lab run that screen-captures the islands writes `{"shown": true}` into its own folder first.
- `state.json` (written by the app shortly after anything changes): what is on screen per island: `open`, `placed`, `side`, `x`, `y`, `width`, `height`.

Coordinates everywhere (files, `--at`, `move`, `list`, `state`) are screen points from the display's top-left corner, y down, and name the island's top-left corner: on the 1728 × 1117 pt built-in display a pill at the right edge reads about `x 1600`.
- `responses/<id>-<ms>-<pid>-<n>.json`: the user's clicks `{island, kind, action, value, at}`. The reader consumes them by deleting them. Kinds: `button`, `list`, `toggle`, `slider`, `closed`, `open`; `tick` (a plan item ticked: `action` `done` | `undo`, `value` the item id); `due` (a Scheduled item fell due; it stays in Scheduled: `value` the item id); `approval` (a proposal answered: `action` `yes` | `no` | `later` or the proposal's own, `value` the item id; from a list's Yes, `island` the list and `value` the proposal's id); `waiting` (a choice on Scheduled's guarantee line: `action` the choice, `value` the waiting item's id); `report` (a page in the viewer called `window.heimdall.send`: `island` the viewer's id, `action`, `value`, `label`).

```json
{
  "id": "tests",
  "preset": "task",                 // task | waiting | result | list | note | viewer | todo
  "title": "Tests",                 // one or two words
  "state": "running",               // running | waiting | done | failed (a done task shows as a result)
  "progress": 0.42,                 // 0..1, only a live measured value (shown as a ring and %); absent: a spinner
  "stage": "Building",              // what a running task is doing, shown when there is no live progress
  "path": "/path/any.file",         // viewer: any file (renderer picked by type, below)
  "actions": [{"label": "Do all of it", "action": "do-all"}],   // viewer: proposed actions, a button row on top
  "value": "412",                   // headline shown in a result's pill
  "open": "https://… or /path",     // shown open as a button that opens it in the default browser or app
  "summary": "One line",            // shown open, under the status
  "steps": [{"title": "Download", "state": "done"}],   // done | now | failed | todo
  "kv": [{"label": "Size", "value": "20 GB"}],         // a few key values
  "image": "/path/picture.png",     // shown open; a click opens it
  "started": 1792596000, "updated": …, "ended": …,     // epoch s, stamped by the CLI (file dates otherwise)
  "parts": [ … ],                   // the open island's own content, below
  "expanded": false,                // open; stays open until a click or an agent closes it (no timers, no hover)
  "hidden": false,                  // off screen, file and place kept
  "side": "right",                  // dock: left | right | top (absent: right; a plan island: left)
  "order": 1,                       // place in its dock, lower first
  "edgeY": 340,                     // pinned on its side edge at this height (its top, from the display's top): written when the user throws or drops it
  "position": {"x": 20, "y": 160},  // placed freely: top-left corner, screen points from the display's top-left; wins over side
  "items": ["Plain", {"title": "Port", "group": "running", "done": false}],   // group: running | waiting | discussed (plan items below)
  "list": "goals",                  // a plan island (preset todo): goals | scheduled | settled
  "attention": "waiting",           // waiting (bell, orange) | question (question mark, blue): a pulse every 6 s while closed
  "origin": {"from": "notch"},      // grows out of the notch: the path for a Heimdall notch panel dragged out
  "sent": "Promote the models",     // a job island: what it was sent to do (written once); switches on the one-system look
  "goal": "g-site",              // a job island: the goal it works for (a chip; lights that goal's bar blue while running)
  "width": 300, "icon": "SF.Symbol.name", "chosen": "action-id"
}
```

Opened, a job island (running, waiting, done, failed) shows its content first: summary, steps, key values, image, parts. Its status is one bottom row (the content gets the room; `mac/glance.rs`, `model/glance.rs`): the open target's chip on the left (`compare3.html ↗`, or `Not found: …` when the file is gone; it keeps at least 45 % of the row), and on the right the stage (orange while waiting, a result's `value` in white), a live graphic with its figure, and a timer glyph with how long it has run or took (redrawn on the minute while open). When the row is crowded the duration goes first, then the stage. The graphic: a running `progress` is a small bar, or a sparkline once the agent rewrote it (its pace; the `line` part's look, small); when the header's icon is the progress ring, only the `42%` stays. Key values earn the same: a share (`7/12`, `42%`) a bar, a number that changed over rewrites (`41 GB`, `31 it/s`) a sparkline, just left of the value; the app keeps each island's numbers in memory (24 points). A sparkline draws itself on arrival; a rewrite draws only its newest step and a bar grows from its last value; nothing moves at rest. Any other island (note, list) shows its status first when it has nothing else to say, and the open target as a button. Lab: `FloatingIslands --render-glance DIR` (with `FLOATING_ISLANDS_DIR`). Heimdall Remote renders `parts` only so far.

Plan islands (left dock, in this order unless `order` or a place says otherwise): `goals` (Goals), `scheduled` (Scheduled), `settled` (Settled), each `preset: "todo"` with `list` naming it and its id the list name; Today (`day`, order 3) docks after them. There is no To do list: an old `todo.json` (or a file whose `list` is "todo") is not drawn and its file is left alone for Heimdall to migrate. The preset name `todo` stays only as a file-format key for list islands; any other `preset: "todo"` island is an agent's own checklist under its own title. Settled is a pill until opened. Closing a plan list (its X, right-click › Close) hides it: the app writes `hidden: true` and `expanded: false` into its file and the `closed` response, and keeps every item (bug 2026-10-31T15-57-16: closing the old list by accident deleted it whole); it comes back when `hidden` is cleared (`islands show <id>`, Heimdall's menu). Any other island's file is still removed on close.

One system (`docs/one-system.md`): nothing enters Goals or Scheduled without the user's yes, nothing settles without proof. Every list keeps the plan-island keys and gains `slate` (epoch s of the clean slate) and `proposals` (the queue, oldest first: `{id, title, why, by, proposed, shown}`; Goals' carry `kind: "goal"` (`icon`, `about`) or `kind: "step"` (`goal`), Scheduled's `due`, `goal`, `icon`). The front is the first not past 48 h since its `shown` (absent: not shown yet, it cannot expire); only it is drawn, as a ghost (an inset hairline box, its title at 75 %, the Yes chip with a small waveform, "+N" for the live ones behind it). A click on its title shows its `why`; Yes is one click (no Sure?): an `approval` response, and a check on the chip until Heimdall writes the yes. A yes keeps the id, so the ghost fills in where it sat. Model: `model/onesys.rs`; marks: `mac/marks.rs`; what one island reads of the others: `mac/world.rs` (redrawn when a job island starts or stops under a goal, or a goal is renamed).

Per active goal: a progress ring round its symbol (conic: green the share done, blue the share running, dim the rest, a soft green glow; over done + running + queued + 1 for its front step), its title (16 pt semibold), a segmented bar (6 pt, 3 pt gaps: green per done task, blue per running job island whose `goal` is this goal, dim per queued task, dashed for its front step proposal; spans per kind past 24), the latest move (`now`) in grey, "N running on the right" in blue with a lit dot, the queued tasks (`next`, and `now` with no running island behind it) as grey-dot lines (three at most), and the front step proposal as a ghost row. Scheduled (`scheduled.json`; `mac/scheduled.rs`): `items` are promises, each with `due` (no `due`, no promise: not drawn); `guarantee` is written by Heimdall's sweep: `{checked, waiting: [{id, title, line, goal, choices: [{label, action}], source}], unsure: [{id, title, line, since}]}`. On top the guarantee line: a green ring, "Nothing waiting on you" and "checked 2 min ago"; an amber dot, the first waiting title, its goal's symbol and title · its line, its choices (the first white; a click asks Sure? then writes the `waiting` response and shows the pick) and "+N"; or "Not sure" with a quartered ring: an unsure entry ("Website picks not heard from in 22 min" with `since`, else its `line`), or no sweep / `checked` older than 30 min ("Not checked for 40 min"). A hairline, then the week strip (now's tick, a white mark per promise due within seven days, a dashed ring at the front proposal's due; Now and the weekdays two, four and seven days on), then the rows by due: "Now" once due, "15:30" today, "Tue 10:00" within the week, then "12 Nov"; the goal's symbol (its `icon`, else its goal's, else the plan symbol rule); the title (two lines). The front proposal is a ghost row at its time's place. Nothing promised or proposed: "Nothing promised". Due items still write one `due` response, as below.

Settled (`settled.json`; `mac/settled.rs`): `items` `{id, title, at, goal, task, kind, quote, by, proof?}`, `proof: {kind: commit|test|file|install|quote, value, label}`; no `proof`: claimed. The big count (28 pt bold) is the proved items since `slate` while it is under a week old ("since the clean slate"), else this week's; "N claimed" beside a dashed pill. Seven day columns (oldest left): a green pill per proved item (7 pt, 3 pt apart, 60 %), a dashed one per claim on top, a dim baseline on an empty day (and every day before the slate), Today in a faint blue column; the count sits over the columns' empty top left unless a stack would run under it. Then today's newest three rows ("03:47", the goal's symbol, the title, the proof chip: commit, test, file, install, quote with its symbol; a claim's dashed "claimed") and "› N earlier today", which unfolds (`settled:all`). A chip shows the proof (label, value) under its row; a file proof also opens (an `open` response, the viewer). Items before the slate or without `at` are not drawn. The closed pill counts what the big number counts.

Job islands with `sent` (`mac/parts.rs`): the `sent` line (14 pt), the goal chip (its symbol and title from Goals), the stage band (kept; its helpers become the count), the fact line: "open turn, 3 helpers" (helpers working now) with a clock, how long it has run on the right (on the minute); done: "This report" (blue outline; opens the `open` target in the viewer) and "lands in Settled"; waiting or failed in their colour. Running with `updated` older than 15 min: the sent line, chip and band at 55 % and "not heard from in 22 min". Without `sent` the old look stays.

`id` is stable across rewrites: the app diffs rows by it to animate (without one, the title). A Scheduled item's `due` (epoch seconds) is when it should happen: the row's right side counts down from the local clock (`in 12 min` at full white within the hour, then `in 3 h`, `tomorrow 10:00`, `in 2 days`, `26 Oct`), redrawn by one one-shot timer at the next moment a label changes (none without due items; re-read after sleep and clock or time-zone changes). When it falls due it stays in Scheduled (what has to happen because it is scheduled lives in Scheduled): it moves to the top and its lead reads "Now" in white (never red, never "overdue"), and the app writes one `due` response (`{"island": "scheduled", "kind": "due", "action": "now", "value": id}`), also for items that fell due while it was not running, never again once Heimdall has stamped `told: <its due>` on the item (Heimdall writes the stamp when it handles the response; the islands app only reads it, and holds what it told in memory until the stamp arrives; a new `due` is told again when it comes). Nothing moves to another list. Every islands-side write of a plan list also refreshes its kept copy `.kept-<list>.json` (a Goals file without goals never replaces a copy that has some), and a writer that finds the file gone starts from `.closed-<list>.json` (still hidden) or the kept copy, never from nothing; a file that does not parse is never replaced. `when` is the label for items without a `due`. An agent's checklist groups its items: Running, Waiting on you, Discussed. Scheduled and Settled draw themselves (above); the rest of this paragraph is the agents' checklists. A row is its tick ring, a small symbol and the title on one line (cut with an ellipsis); nothing else shows until it is opened (titles only, no wall of text). The symbol is the item's `icon` (SF Symbol), else picked from the project prefix of its title, then the title (`PLAN_SYMBOLS` in `model/plan.rs`, `Plan.symbols` in Swift: Heimdall an eye, Echo a speaker, Voices a waveform…), else its kind. Ticked items sink to the bottom of their group, struck and stepped back to 70 %. A click on the ring ticks it (`tick` response, file updated). A click on the rest of a row with a `detail` or an open `proposal` opens it in place: the title wraps, the whole `detail` follows at the island's width (13 pt, secondary grey), then the proposal and its buttons (actions default to Yes / No / Later); the island grows, capped under the screen and scrolling beyond. A second click closes it. A row with neither ticks wherever it is clicked. A button writes an `approval` response and `chosen` on the item, shows the choice, and closes after 1.4 s (Rust then moves the item). The app keeps every unknown item key.

Settled's older day-column chart (with a running total and kinds) was replaced by the one-system Settled above; `lab/settled_island.sh` still renders its states with the new drawing.

Plan rows animate on the grow spring and nothing runs afterwards: an added row slides in under a soft highlight that fades (1.4 s); a ticked row fades to done and slides to the bottom of its group; a moved row slides to its new place above the rows it crosses; a removed row fades while the rest close up; between islands an item leaves one and arrives in the other. The shape resizes on the same spring. A closed list that changes takes one breath of its symbol.

Attention: `attention` on any island, or derived `waiting` on a plan island with an open waiting item. While it is set and the island is closed, its symbol becomes a bell (orange `#FF9F0A`) or a question mark (blue `#0A84FF`) and one pulse plays every 6 s: a soft glow of that colour across the pill and its edge, the bell rings or the question mark bounces (about 1.3 s), then nothing moves until the next one (one timer; no display link). Opening the island clears it; it shows again only for something new (another waiting item, a new question's buttons) or when the key comes back.

Every island that appears while the app runs drops out of the notch into its slot (any writer: Heimdall's tools, the CLI, a refresher); islands already in the folder at launch appear in place. `origin: {"from": "notch"}` asks for the same explicitly: the island grows out of the notch (the gap between the screen's `auxiliaryTopLeftArea` and `auxiliaryTopRightArea`; a small rect at the top centre on a display without one) into its slot on the open spring, and the app drops the key.

Height: no island is taller than its display: open, it is capped a little under the room between the menu bar and the Dock, and longer content (a long plan list) scrolls inside it: trackpad momentum and rubber band from the system's own scroll events, a wheel in eased steps, soft edges where content continues, an overlay indicator that fades when it stops. Closed and reopened, it starts at the top.

Answers ask first: a click on a button, a proposal's action or a viewer's action turns its row into `Sure?  Confirm  Cancel`, Confirm in the clicked button's place. Confirm (or a second click there) within 4 s sends it; Cancel, or nothing, puts the row back. "Later" goes in one click. `lab/lane_islands.sh <out>` checks all three offscreen.

Parts (consecutive buttons share a row, at most three):
`timeline {from, now, blocks:[{start, end, kind, title, line}]}` (Heimdall's Day Timeline, Rust build only: a day ribbon of the blocks in their kind's colour with a tick at now and hours under it, then a row per block: start time, a rail that grows with its length, title, length and one line; kinds `build` `talk` `people` `web` `play` `other`; `model/timeline.rs`) · `text {value}` · `stat {value, unit, baseline:{label, value}}` · `bars {items:[{label, value, highlight}], unit, max}` · `line {points, unit}` · `list {items:[{id, title, value}], selected}` · `image {path}` · `button {label, action}` · `toggle {id, label, on}` · `slider {id, min, max, step, value, unit}`.

## CLI (`build/bin/islands`)

`islands --help` is the agent's reference; `islands put --help` covers one call carrying a title, stage, summary, steps, items, key values, image, open target and place; `islands plan --help` the plan lists. The words follow `docs/island-style.md`, and `put` refuses a missing or id-like title, a title over 3 words, a stage over 2 words and a summary over one line.
```
islands put <id> [--title T] [--state running|waiting|done|failed] [--stage WORDS] [--summary TEXT]
                 [--step "TEXT[=done|now|failed]"]... [--item "TEXT[=running|waiting|discussed|done]"]... [--kv "Key=Value"]...
                 [--progress F|none] [--image PATH] [--open URL|PATH] [--icon SF.Symbol] [--value V] [--preset P] [--parts JSON]
                 [--side left|right|top | --at X,Y | --auto] [--order N] [--expanded | --collapsed] [--from-notch] [--json JSON | -]
islands plan [goals|scheduled|settled] [list] | add "TEXT" [--due TIME] [--when W] [--detail T] [--proposal TEXT] [--item-id ID] [--goal ID]
             (one system: add and move --to refuse Scheduled and Settled; promises are proposed for the user's yes and
              Settled fills from proof, both through Heimdall's plan_edit; ISLANDS_LAB_PLAN_WRITES=1 for lab fixtures)
             | done|undo|rm N|ID|"TEXT"... | move N|ID|"TEXT" [--to goals|scheduled|settled] [--due TIME] [--when W] | prune
                                  (LIST defaults to goals: the verbs work on its asks; `list` also prints its goals compactly)
islands view <path> [--id ID] [--title T] [--action "Label=action"]...
islands open|close|hide|show <id>…
islands move <id> X Y | <id> --side left|right|top | <id> --auto
islands rm <id>… | --all · islands clear   (never a plan list: put and rm refuse goals, scheduled and settled, and --all and clear leave them; edit them with islands plan) · islands list [--json] · islands state [<id>] [--json]
islands responses [--consume] [--json] · islands quit · islands dir
```
`--open` and `--image` resolve a relative path against the caller's folder; a bare domain gets https. `--step`, `--item` and `--kv` replace their lists on each call (`none` clears).
`put` merges into the existing file, so a place the user chose survives agent updates unless `--side`, `--at` or `--auto` is given.

## Viewer (`preset: "viewer"`, `islands view`)

Any file opens large in the middle of the screen, renderer by type (`IslandModel/ViewerKind.swift`, extension then UTType, else a UTF-8 sniff): markdown rendered (headings, lists, task boxes, quotes, code blocks on a dark block, real tables); text and code monospaced with light colouring (Xcode's dark palette, up to 200 KB); images; PDF (every page, scrolling, sized so the first page fits whole); audio (play/pause, a waveform drawn once from the file, click or drag to scrub, elapsed and total time); video (AVPlayerView with inline controls); HTML and SVG (WebKit, read access to the file's folder, the island sized to the page); anything else through QuickLook; a gone file says "Not found". The size is known at once from header reads; text over 150 KB (read up to 2 MB), PDFs and waveforms load off the main thread and the island resizes when the real height arrives. Closing the viewer pauses media; removing the island stops it. An open viewer watches its file (its own watch and its folder's, so a save by rename is seen too; no polling) and re-renders about 150 ms after a change, keeping its scroll position; a viewer opened again, or rewritten with the same path (`islands_view` stamps `updated` each call), reads the file anew when it changed since it was loaded (inode, size or modification time). The pill's symbol follows the kind.

Report bridge (`docs/one-system.md`): an HTML page in the viewer has `window.heimdall.send(action, value, label)` (defined before its scripts run; a `heimdall-ready` event on `document` and `window` says it is there) and may also call `window.webkit.messageHandlers.heimdall.postMessage({action, value, label})`. Each message writes `{island: <viewer id>, kind: "report", action, value, label}`. `action: "save"` with `value: {file, data}` first writes `data` as pretty JSON to `file` beside the page (temp file and rename) when `file` is a bare `*.json` name (no folders, no hidden file, no `..`; `model/onesys.rs::save_name_ok`); the response's value then carries `saved` (the path) or `refused`. Fixture: `lab/fixtures/report-bridge.html`; `--viewer-shots` checks it offscreen (`viewer-bridge` lines in its report).

Drag handle (drags the whole file into a chat; Rust build only, `mac/share.rs`, `model/share.rs`): an open viewer of a file that is there shows the file's own Finder icon in its title row, left of the X, quiet at rest (45 %); the pointer over it lifts it on a soft rounded backdrop (one tracking area, nothing runs at rest). Dragged, it is a real file drag (a file URL on the drag pasteboard, its icon as the drag image): chats, Mail, Finder and browser uploads take the file. Clicked, the file goes on the clipboard as a file and the icon is a green check for 1.2 s. An HTML page that loads files from its own folder (images, `srcset`, stylesheets with their `url()` and `@import`, style blocks and attributes, scripts, posters, frames) goes as one self-contained copy with those files inlined as data URIs (64 MB a file, 160 MB in all), same name, alone in a fresh folder under `$TMPDIR/FloatingIslands-shares` (a lab run: `<lab dir>/shares`); copies older than a day are swept at launch and at each new share. Files outside the page's folder (`..`, symlinks out), hidden files and folders, and files of the wrong kind for their element (an image element takes only images, a script only JavaScript, a stylesheet only CSS) are never inlined, so a page cannot carry a key or a document out through a hidden element; a page directly in the home folder or at the root is not bundled. Remote URLs, links between pages and what scripts fetch are left as they are; anything else goes as it is. The copy is reused while the page and its files are unchanged, and made in the background when the pointer comes over the handle. `lab/share_check.sh <out>` checks it offscreen: the copy drawn against the original (pixel diff), a lone .html as the broken control, the title row at rest, on hover and after a click, and a real drag session begun and ended off every display, read by a drop target in another process (`lab/tools/drop_target.swift`); the pointer and clipboard are never used.

Proposed actions (`actions`, or `--action "Label=action"`; no `=`: the label's slug) are island buttons on top of the open viewer, at most three a row, the first one primary (white). A click writes `{"island": id, "kind": "button", "action": …}` and shows the choice (a check, the others dimmed) for 1.6 s; the buttons stay for another choice.

## Placement and motion

- Islands never enter the menu bar strip. Three docks: a column at the right edge (the default) and one at the left edge (the plan lists'), each 8 pt in, starting 60 % of the display's height up from its bottom (the top corners, where websites keep their controls, stay empty), stacking downward 8 pt apart; a stack too tall for that moves up only as far as it must to stay on screen, a full column continuing inward; and a row under the notch, 6 pt below the menu bar, centred on the notch. Docks step past placed islands and close up when one leaves. Placed islands keep their place.
- Opening an island in a dock pushes the rest of its stack along (down in a column, sideways in the top row) on the same spring, and they slide back on close. Its content scales with the shape (Dynamic Island style), so it is never cut and the shape is never empty.
- Every island has a 0.75 pt white hairline at 20 % so black islands read on black and dark backgrounds.
- Every island opens and closes whatever its preset or state. A click on a pill opens it; a click on an open island's title row minimises it (also right-click › Minimise, Esc on a viewer, `islands close`); the rest of an open island does only what its controls do. Close for good: the X on any open island (24 pt target), or right-click › Close on a pill or an open island; the agent gets a `closed` response. The open button (and right-click › Open …) opens the target in the default browser or app; the agent gets an `open` response.
- Answering a question shows the choice for a moment, then the question leaves.
- Symbols say what the work is and its state: the island's own `icon` (SF Symbol) white and still while it runs (a still quarter arc without one), orange while it waits on the user, a green check when done, a red cross when failed; a change of state swaps the symbol with a bounce. When the agent changes a running island, its symbol takes one breath (the arc turns once); a new question pulses twice. Nothing loops.
- Open and closed change only by a click or by the file; the pointer passing over an island does nothing, and nothing closes on a timer.
- Drag anywhere, open or closed (an open viewer by its title row); carrying changes position only (an open island stays open at the same size).
- Throw (iPhone picture in picture): on release the pointer's velocity over the last 80 ms projects the island forward (scroll deceleration 0.998/ms, about half a second of travel) when it was released at 500 pt/s or faster. Thrown or dropped, it attaches to the side edge (left or right) nearer the projected centre, at the height it lands, and keeps that height (`side`, `edgeY`); never into the menu bar or below the screen, and never to the row under the notch. Each axis springs from the release velocity (0.4 s, damping 0.78), so it carries on the way it was thrown and curves onto the edge. The rest of that edge makes room: unpinned islands take their turn around pinned ones, an island dropped onto another goes above or below it by which is higher, and an open island pushes what is under it down. An agent's `put` keeps the place; `--side`, `--order`, `--at`, `--auto` and `move` replace it.
- Shape motion: one black shape per island on Heimdall's springs (grow 0.45 s / 0.82, retract 0.34 s / 1.0, snap 0.42 s / 0.68), with radius `clamp(10 + (h − 32) × 0.4, 10, 24)` and continuous corners. While a shape moves or resizes, its window covers the old and new rects; the spring runs in the render server, and the window shrinks to the shape when the spring settles.
- Still during Space swipes: the panels join a private SkyLight space (`OverlaySpace.swift`: `CGSSpaceCreate`, `CGSSpaceSetAbsoluteLevel` 100, `CGSShowSpaces`, `CGSAddWindowsToSpaces`). With `canJoinAllSpaces` alone they slide out with the old Space and in with the new one (`FI_OVERLAY=standard` reproduces this for comparison).
- At rest nothing animates: no display link and no loops. An island arms at most three repeating timers, and only while its window is on screen (all shown, or up alone for news while hidden) and not leaving (`model/toggle.rs::timers`): a running task's breath every 4 s (`WORK_INTERVAL`), an open body's duration line on the minute with 2 s leeway so every island's clock fires together, and the attention pulse every 6 s. Hidden islands run none. Measured 21 Oct with four islands on screen: app 0.00 % CPU over 2 × 30 s (the breathing build: 0.03 %); the self-test checks that no layer animates at rest.
