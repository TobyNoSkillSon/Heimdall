# Parakeet vocabulary biasing

The default Metal Parakeet TDT decoder biases a short list of names toward their spelling and applies an
English/Polish language prior. It changes token selection before the prediction network consumes the token; it never
rewrites a finished transcript. Code: `crates/listen/src/vocabulary.rs`.

- Personal edition: 20 words in `crates/listen/src/default-vocabulary.json` (entries may be phrases: `T3 Code`).
- Public edition: `public-vocabulary.json` (Heimdall, Claude, Codex, T3 Code) and no language prior (penalty 0).
- Personalise: the assistant's name, when it is not Heimdall, is added at the next model load
  (`vocabulary::set_extra_words`, from `app/src/identity.rs`), within the 128-word bound.

## Language prior

Parakeet v3 has no language input; on accented or short speech it drifts into
its other languages (19 Oct: `Инстаграм?`, `Ол Райт`, `Haimdāl`, `Nej, så är man`,
`Hallo, Heimdal, je daar?`). The default build serves English and Polish, so the same bias
table subtracts `foreign_penalty` (default 6.0) from every piece that English and
Polish never produce: any letter outside the English and Polish alphabets
(Cyrillic, Greek, ä/é/š…), and 530 word-initial Latin pieces only other languages
use (`src/foreign-pieces.json`, regenerated by `crates/listen/scripts/foreign_pieces.py`
from frequency lists, exempting every prefix of a common English/Polish word or a
word in a corpus of technical docs, so ` var`, ` seg`, ` vec` stay free). It holds
in every prefix row, never touches blank, and never penalizes a piece on a
configured vocabulary path. It is a penalty, not a mask: a foreign piece still
wins when it leads by more than 6 logits.

Limit: Dutch respelled from shared pieces is not caught. With the penalty,
` daar` gives way to ` da` + `ar` (0.5 % probability) and the text stays
`je daar`; only a language-conditioned decoder would fix that.

## Decoder behavior

`listen::vocabulary::Vocabulary` builds a case-insensitive prefix automaton over
the model's 8,192 SentencePiece tokens. Each prefix row contains the next state
and an additive logit bonus. The resident GPU decoder looks up this row inside
its existing token-decision kernel, without another GPU dispatch or host readback.

The default boost is 4.0: exact word-start pieces of at least two letters receive
1.0. Complete observed sound-alike entry pieces receive 2.0, capped at 2.0 even
with a higher configured boost. Incomplete acoustic entry fragments and
contraction fragments receive no bonus; the common `Al` entry is admitted
without a start bonus. Continuations receive 4.0, and a continuation that
completes a configured word of at least four letters receives 8.0. A single-letter
start can establish a prefix but receives no bonus.
Word starts require a SentencePiece boundary; arbitrary interior fragments cannot
start a name. An unfinished path can cross a SentencePiece boundary (`Hi Mdal`,
`Nemo Tron`).
A mismatched emitted token resets the prefix. Blank tokens retain
it, but a prefix expires more than eight encoder frames after the last emitted
token (640 ms at the model's 80 ms frame interval). Each encoder window starts
with a fresh prefix.

Blank itself receives no bonus. When blank wins acoustically, bias may override
it only with a token that completes a configured word. This gate prevents an
unfinished name from consuming unrelated speech. Selected-token confidence is
calculated from the original acoustic logits, so boosting cannot inflate it.
The duration decision, ten-symbol frame guard, and token guard remain in force.

Exact configured names receive canonical capitalization. A small explicit table
of observed entry spellings admits `Hi`/`Hem`/`Him`/`I'm`/`Hi'm` into
Heimdall paths, `Qu`/`Ku` into Qwen, `Nimo` into Nemotron, `Sile` into Silero,
`Al` into Ultron, `mop` into Mobius, `parakit` into Parakeet and `tifri` into T3 Code (the decoder's ` T` `if` `ri`
route, "Tifrico"); the table is `ENTRIES` in `vocabulary.rs`. Heimdall paths also accept the observed `dahl` ending.
The remaining suffix must complete; no general edit-distance or phonetic search
runs over transcripts. The same transition policy builds the GPU tables and
recognizes completed token spans for canonical rendering. A completed span joins
its pieces, keeps its first timestamp and last end timestamp, and takes the
minimum original token confidence. Failed or expired entries keep their original
text. It also separates a following joined alphabetic token (`Heimdallbug`).
Before inserting that boundary, it checks the complete joined tail across token
pieces: ordinary suffixes (`s`, `es`, `ed`, `d`, `ing`, `er`, `ers`, `est`,
`ly`, and possessive apostrophe-s) stay attached. An explicit SentencePiece
boundary still starts a new word. Thus `har` + `ness` + `e` + `s` renders
`harnesses`, while `Heimdall` + `s` + `ystem` renders `Heimdall system`.
Words of two or three letters receive neither the completion flag that can
override blank nor the extra completion bonus or joined-word split. `VAD` is the
only such word retained by the measurement; `Pi`, `Sol`, `Mac`, and the other
short candidates are absent from the default list.

## Configuration and app wiring

`Parakeet::set_vocabulary(Vocabulary { words, boost, foreign_penalty })` applies on the next decode
without reloading the model. The recognizer retains the configuration across GPU
recreation and recovery. Startup also accepts `HEIMDALL_ASR_VOCABULARY` as a JSON
array of words, `HEIMDALL_ASR_VOCABULARY_BOOST` and `HEIMDALL_ASR_FOREIGN_PENALTY`
(0 disables the prior) as numbers. Unset values select the committed list, 4.0 and
6.0 (0 in the public edition). A supplied list replaces the default list; include `Heimdall` to retain it. An empty list provides the unbiased evaluation control.

Entries are letters and digits, words separated by single spaces, with at least
one letter, at most 64 characters each. Limits are 128 entries, 1,024 distinct
prefix nodes, a finite boost from 0 through 8 and a penalty from 0 through 16.
Apostrophes and hyphens are not accepted. A phrase is matched without its spaces
across SentencePiece boundaries (` T` `3` ` Co` `de` → `t3code`) and rendered as
one word per phrase word, sharing the span's time by character count. The tables occupy
`prefix_nodes × 8193 × (4-byte state + 4-byte bonus)` bytes
on each of the host and GPU, plus the small GPU prefix state. Exact node count
includes explicitly configured acoustic entry paths.

The app's worker, lazy replay and backend hot swaps all construct through `Parakeet::load_backend`, so the defaults
reach production without an app override. There is no vocabulary menu setting. A future live setting would send the
list to the listen worker that owns `Parakeet`, call `set_vocabulary` between decodes, and keep the previous list on a
validation error, never rebuilding the recognizer or dropping active utterances.

The Core ML recovery backend exposes only the joint model's already-selected
token, not its logits. It retains the configured list and canonical formatting,
but **does not perform token biasing**. Recognition improvement therefore applies
to the default Metal path and returns when GPU recovery succeeds.

## How the list was chosen

Each word earned its place on measured archive and Vella clips (`heimdall-listen-file --whole`, default Metal path,
M5 Max). The rule: a word stays only if it repairs mentions and changes no ordinary control text.

- 17 Oct, initial list: 93 candidates → 15. On 180 positive clips exact listed-word mentions rose 61 → 107 (46
  reviewed repairs, zero losses); 200/200 controls byte-identical. Dropped for changing controls or ambiguity:
  `threads`, `DeepSeek`, `spindump`, `Grok` (confused Groq), `Sol`, `Kimi`, `Vireo`. The `Va`/`Vi` Vella entries and
  the broad `Hi + dall` Heimdall route were removed after false insertions.
- 17 Oct, fix round: `Claude` and `Poznań` added (contextual repairs, zero control changes).
- 20 Oct: `T3 Code`, `Parakeet`, `oMLX`, entries `tifri`→T3 Code, `parakit`→Parakeet, `mop`→Mobius, and
  the language prior. Added words changed 0/200 controls; the prior changed 2/200, both already non-English. Labelled
  moments WER 12.89% → 12.85%. `thread`/`threads` again made 3/200 controls worse and stay out.
- Decode cost (12 Oct, single-word list): median +0.07 ms per decode, no TDT slowdown. Longer lists were not timed.

Not measured: Polish name recognition, long-list cost, live command-trigger recall, the Core ML fallback.
Receipts were local (`target/asr-vocabulary-eval/`, `target/asr-names/eval/`) and are not in Git;
a scoring script in the lab recomputes mentions and control changes from new receipts.
